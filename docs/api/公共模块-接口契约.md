# 公共模块接口契约（冻结）

> 本文是乌东文旅平台**公共层**的权威契约，供后续衣食住行社区等业务板块 subagent 查阅。
> 对应实现计划 `docs/superpowers/plans/2026-09-09-公共模块.md`（D1–D10 决策 + 全局约束）。
> 冻结后不得单方面修改；如需变更，先回看计划文档并与主会话对齐。

---

## 一、全局约定

| 项 | 约定 |
|---|---|
| 框架 | Cool Admin 8.0（Midway v3.20.3 + Koa + TypeORM `@midwayjs/typeorm`） |
| 建表 | TypeORM `synchronize:true` 自动建表（`config.local.ts`） |
| 金额 | 一律「分」，`INT` + `unsigned:true`，禁止 DECIMAL/FLOAT |
| 新实体基类 | 一律 `extends BaseEntity`（`src/modules/base/entity/base.ts`，含 `id`/`createTime`/`updateTime`/`tenantId`） |
| 时间字段 | 沿用 `BaseEntity` 的 `createTime`/`updateTime`（varchar + transformer） |
| 密码算法 | 沿用 Cool Admin 的 md5（`TODO(bcrypt)`，D9） |

### 响应格式

- 成功：`{ "code": 1000, "message": "success", "data": ... }`（`BaseController.ok()` 返回）
- 业务错误：`{ "code": <号段>, "message": "..." }`，HTTP 状态 200
- 错误一律 `throw new BizException(code, msg)`，**禁止**手写 `{code,message,data}`

### 错误码号段（设计文档 §6.2）

| 号段 | 归属 |
|---|---|
| 10000–19999 | 公共 |
| 20000–29999 | 用户 |
| 30000–39999 | 衣 |
| 40000–49999 | 食 |
| 50000–59999 | 住 |
| 60000–69999 | 行 |
| 70000–79999 | 社区 |
| 80000–89999 | 管理 |
| 90000–99999 | 订单/支付/库存 |

已定义错误码（`src/common/constants/error-code.ts`）：`PARAM_ERROR=10001`、`NOT_FOUND=10004`、`SYSTEM_ERROR=10005`、`LOGIN_INVALID=20001`、`ORDER_NOT_FOUND=90001`、`ORDER_STATUS_INVALID=90002`、`STOCK_NOT_ENOUGH=90003`、`PAY_FAIL=90004`、`CART_ITEM_INVALID=90005`。

### 鉴权约定

- **C 端（`controller/app/`）**：默认需要用户 token，当前用户取 `ctx.user.id`（`@Inject() ctx`）。
- **开放端（`controller/open/`）**：方法上加 `@CoolTag(TagTypes.IGNORE_TOKEN)` 免鉴权。
- **后台（`controller/admin/`）**：默认需要 admin token，当前管理员取 `ctx.admin.userId`/`ctx.admin.username`。
- 超管判断：`ctx.admin.username === 'admin'`。

## 二、订单中心（order 模块）

### 常量（`src/common`）

- `BizType`：`GOODS`（衣、食特产）｜`SEAT`（餐位）｜`STAY`（住）｜`TICKET`（门票）｜`ROUTE`（路线）
- `OrderStatus`：`PENDING → PAID → CONFIRMED → ONGOING → FINISHED → REVIEWED`，另 `CANCELLED`/`CLOSED`/`REFUNDED`
- `canTransit(from, to)`：状态机校验（`src/common/order-status.ts`）

### REST 接口（均需 C 端登录）

| 方法 | 路径 | body |
|---|---|---|
| POST | `/app/order/create` | `{ merchantId?, bizType, totalAmount(分), payAmount?(分), items[], ext{}, clientRequestId?, addressSnapshot?, remark? }` |
| POST | `/app/order/cancel` | `{ id, reason? }` |
| POST | `/app/order/refund` | `{ id, reason?, penaltyRate? }` |
| POST | `/app/order/list` | `{ page?, size?, status?, bizType? }` |
| POST | `/app/order/detail` | `{ id }` |

`items[]` 结构：`{ targetId?, skuId?, name, skuName?, price(分), quantity, imageUrl? }`（下单快照）。

### 服务契约（业务板块注入 `OrderService`）

```typescript
class OrderService {
  create(userId: number, data: CreateOrderData): Promise<any>;
  //   幂等：clientRequestId 重复提交返回原单（data.clientRequestId 必传用于幂等）
  //   事务内写入 ord_order + ord_order_item + ord_ext_* + ord_order_log

  changeStatus(id: number, to: string, operatorId?: number, remark?: string): Promise<any>;
  //   状态机唯一入口：canTransit 校验 + 乐观更新（以旧 status 为条件）+ 写日志 + 发事件

  cancel(id: number, userId: number, reason?: string): Promise<any>;
  refund(id: number, userId: number, reason?: string, penaltyRate?: number): Promise<any>;
  //   penaltyRate 0~1，生成 ord_refund + 状态流转 REFUNDED

  pageByUser(userId: number, query?: any): Promise<{ list, pagination }>;
  detail(id: number, userId?: number): Promise<any>; // 含 items + refunds + ext

  createFromCart(userId: number, groups: any[], address?: any, remark?: string): Promise<any[]>;
  //   接收「已分组」订单参数数组（按 merchantId 拆单由业务板块完成），逐单 create
}
```

`CreateOrderData`：

```typescript
{
  merchantId?: number;
  bizType: 'GOODS' | 'SEAT' | 'STAY' | 'TICKET' | 'ROUTE';
  items: Array<{ targetId?; skuId?; name; skuName?; price; quantity; imageUrl? }>;
  totalAmount: number;   // 分
  payAmount?: number;    // 分，缺省等于 totalAmount
  ext?: Record<string, any>;  // 板块扩展字段，按 bizType 写入对应 ord_ext_* 表
  clientRequestId?: string;   // 幂等键（前端 UUID）
  addressSnapshot?: any;      // 实物订单收货地址快照
  remark?: string;
}
```

### 订单扩展表分发（`OrderExtService.write`）

| bizType | 扩展表 | 说明 |
|---|---|---|
| `GOODS` | `ord_ext_goods` | 收货人/物流 |
| `SEAT` | `ord_ext_seat` | 预订日期/时段/人数 |
| `STAY` | `ord_ext_stay` | 入住/离店/入住人 |
| `TICKET` / `ROUTE` | `ord_ext_ticket` | 使用日期/游客/核销码 |

### 事件（`@CoolEvent` + `@Event`，本进程）

`OrderService.changeStatus` 成功后广播 `order.<status小写>`：

- `order.paid` / `order.cancelled` / `order.refunded` / `order.closed` / `order.confirmed` / `order.ongoing` / `order.finished` / `order.reviewed`
- payload 为**完整订单对象**（含 `orderNo`/`bizType`/`id`/`userId`/`merchantId`/`totalAmount`/`payAmount` 及更新后 `status`）。

订阅示例（业务板块）：

```typescript
@CoolEvent()
export class MyEvent {
  @Event('order.paid')
  async onPaid(order) { /* order.orderNo, order.bizType, order.id ... */ }
}
```

## 四、支付（pay 模块）

| 方法 | 路径 | 鉴权 | body |
|---|---|---|---|
| POST | `/app/pay/pay` | C 端登录 | `{ orderNo }` |
| POST | `/open/pay/notify` | 免鉴权 | `{ out_trade_no }`（幂等） |

服务契约：

```typescript
class PayService {
  pay(orderNo: string): Promise<{ paid: boolean; payNo?: string; reason?: string }>;
  //   mock 直接改订单状态为 PAID
  handleNotify(payload: any): Promise<{ code: 'SUCCESS' | 'FAIL' }>;
  //   重复回调幂等（已非 PENDING 则直接 SUCCESS）
}
```

支付抽象（`PayProvider` 接口，默认 `MockPayProvider`，后续切换微信支付不改接口）：

```typescript
interface PayProvider {
  createPayment(orderNo: string, amountFen: number): Promise<{ payNo: string; prepayId?: string }>;
  queryPayment(orderNo: string): Promise<'SUCCESS' | 'PENDING' | 'FAIL'>;
  refund(orderNo: string, amountFen: number): Promise<{ refundNo: string }>;
}
```

## 十、跨板块红线（全局约束）

1. 业务板块只允许 import `src/common/*` 与公共层 Service（`src/modules/{order,cart,pay,favorite,message,sensitive,merchant}/...`），**禁止** import 兄弟业务板块的 Service。
2. 库存/房态/餐位/门票一律「条件更新 + 乐观锁」，禁止「先查再改」。
3. 订单 `status` 写权限只归 `OrderService.changeStatus()`，其他板块只读。
4. 金额一律「分」+ `INT unsigned`。
5. 新增枚举放 `src/common/constants/`；新实体 `extends BaseEntity`；每模块需 `config.ts`。
