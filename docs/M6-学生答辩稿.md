## 3. 技术选型：为什么是 Midway.js v4 + TypeORM 原生自建

一开始需求书里提到可以用 Cool Admin，但小组评估后选择了**原生自建**，主要考虑三点：

1. **课程学习价值**：用原生框架写 Controller → Service → Entity，能真正理解依赖注入、装饰器、TypeORM 实体关系；Cool Admin 的封装会跳过这些关键环节。
2. **可控性**：Midway.js v4 + TypeORM 0.3.x + MySQL 8 + Redis 7 的链路清晰，出问题能一层层定位；Cool Admin 的模块黑盒一旦报错很难排。
3. **项目边界**：我们做的是完整平台，不只是后台；原生自建方便六个模块共用同一套用户/订单/支付/消息等公共能力，不需要适配 Cool Admin 的模块协议。

所以 M-6 的后端是 `server/src/module/admin/admin.module.ts` 单文件承载平台管理接口，再配合 `clothing.admin.ts`、`food.admin.ts`、`hotel.admin.ts`、`travel.admin.ts` 给商家端用。

## 4. 关键技术亮点

### 4.1 鉴权：从 `@Auth` 装饰器失败到路径前缀粗粒度拦截

早期尝试用 `@Auth('admin')` + `Reflect.getMetadata` 做鉴权，但全局中间件在路由匹配之前执行，`ctx.handler` 还没挂上，metadata 永远是空的，导致管理员接口未登录也能访问。

我的修复思路改成**路径前缀 + 角色检查**：

- `/api/auth/*` → 公开
- `/api/admin/*` → 仅 admin
- `/api/{clothing|food|hotel|travel|community}/admin/*` → 仅 admin
- `/api/{clothing|food|hotel|travel}/*` → 商家或管理员
- 其它 `/api/*` → 登录即可

代码在 `server/src/middleware/auth.guard.ts`，实测 8 种角色×路径组合全部符合预期。

### 4.2 Dashboard 数据可视化：ECharts 5.6 + 苗韵国风配色

看板做了两张图：

- **GMV / 订单趋势**：混合柱状图 + 折线图，展示近 7 日数据。
- **订单状态分布**：圆环图，7 种状态对应青绿/靛蓝/银饰黄/红等苗族传统色调。

实现上用了 `echarts/core` 树摇导入（只注册 CanvasRenderer、LineChart、BarChart、PieChart、Tooltip/Legend/Grid/Title 组件），避免打包整个 ECharts。

过程中踩过一个坑：折线图配置写成了 `symbol: { size: 8 }`，ECharts 期望 `symbol: 'circle'` + `symbolSize: 8`，导致 `symbolType.indexOf is not a function` 报错，整个 Vue 渲染中断。升级 ECharts 5.6.0 并修正写法后解决。

### 4.3 苗韵国风 UI + 深色模式

后台主题色取自苗族银饰与蜡染：

- 主色：青绿 `#0e8c7e`
- 辅色：靛蓝 `#2d4a7c`
- 点缀：银饰黄 `#c08a3e`
- 背景：米黄 `#f5f1e8`

全局用 CSS 变量定义，Element Plus 通过 `--el-color-primary: var(--color-primary)` 复用。深色模式通过 `html.dark` 类覆盖变量，并监听 `MutationObserver` 让 ECharts 图表文字/坐标轴颜色自动变浅。

新增组件：

- `AppBreadcrumb.vue`：自动根据路由 `meta.title` 生成面包屑
- `ThemeSwitch.vue`：太阳/月亮图标切换，持久化到 `localStorage['wudong-theme']`
- `EmptyState.vue`：空数据状态（数据/搜索/权限三种 SVG）
- `MiaoPattern.vue`：SVG 苗银花纹装饰

### 4.4 演示数据：mock 生成器

答辩前需要让看板有数据。我写了 `sql/03-gen-mock.js`，生成 100 名用户、覆盖 8 种状态的订单、评论、消息、访问日志，追加到 `sql/02-dml.sql`。后端 dashboard 接口会聚合这些真实落库数据，而不是前端写死。

## 6. 我踩过的坑 & 怎么修的

| 问题 | 原因 | 修复 |
|------|------|------|
| 圆环图/趋势图不显示 | `symbol: { size: 8 }` 非法，且 legend.data 触发 ECharts 5.5.1 bug | 改为 `symbol: 'circle'` + `symbolSize: 8`；移除 legend.data；升级 echarts 到 5.6.0；加 `dashboardLoaded` 守卫 |
| GMV 看板显示 ¥0 | 后端返回 `gmv` 为数字，模板误按对象读 `gmv.total` | 模板改为 `adminData.gmv ?? 0` |
| `@Auth` 装饰器失效 | 全局中间件执行时 `ctx.handler` 未挂载 | 改为路径前缀粗粒度鉴权 |
| 深色模式下图表文字看不清 | ECharts option 颜色写死为深色 | 监听 `html.dark` 类，图表颜色动态切换 |

## 7. 总结

M-6 模块的核心价值是**把平台运营能力和商家经营能力集中到一个后台**，让平台管理员能“看得见、管得住”，让各品类商家能“管得好自己的一亩三分地”。

技术选型上坚持原生自建，虽然比 Cool Admin 多踩了一些坑，但对课程学习和后续维护都更透明。答辩时我会用真实账号、真实数据走完整流程，欢迎各位老师提问。
